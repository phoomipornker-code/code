# CV/CC Controller — แปลงจากบล็อก Simulink เป็นโค้ด Arduino

โค้ดชุดนี้คือการแปลงบล็อกไดอะแกรมควบคุมแบบ CV/CC (Constant Voltage / Constant
Current) จาก MATLAB Simulink มาเป็นสเก็ตช์ Arduino ที่คอมไพล์และรันได้จริง

## วงจรกำลังที่ควบคุม

| รายการ | ค่า |
| --- | --- |
| โทโพโลยี | ฟอร์เวิร์ดคอนเวอร์เตอร์ (มีหม้อแปลงแยกกราวด์) |
| ความถี่สวิตชิ่ง | 67 kHz |
| แรงดันขาเข้า | 155 V |
| แรงดันขาออกสูงสุด | 58 V |
| กระแสขาออก | 5 A |
| โหลด | แบตเตอรี่ (ใช้เป็นเครื่องประจุไฟ จึงต้องมีทั้งโหมด CV และ CC) |

## เส้นทางสัญญาณ

```
58 V --(-)-- ZOH [V_OUT] --> Kp=0.1 --> sat --(+)
                             Ki --> K*Ts/(z-1) --(-) --> [CV] --+
                                                               (min) --> sat --> D->P --> [PWM]
 5 A --(-)-- ZOH [I_OUT] --> Kp=1.0 --> sat --(+)               |
                             Ki --> K*Ts/(z-1) --(-) --> [CC] --+
```

แนวคิดคือลูปแรงดันและลูปกระแสคำนวณค่าดิวตี้ที่ตัวเองต้องการแยกกัน แล้วบล็อก `min`
เลือกค่าที่น้อยกว่า ลูปที่ให้ค่าน้อยกว่าคือลูปที่กำลังจำกัดการทำงานอยู่ ซึ่งเป็นวิธี
ที่ทำให้เครื่องประจุไฟไหลจากโหมด CC ไปโหมด CV ได้เองโดยไม่ต้องมีตัวสลับโหมด

บล็อก `sat` ทั้งสามตัวตั้งลิมิตไว้เหมือนกันคือ `0` ถึง `0.41` เลข `0.41` ไม่ใช่ค่าที่
จูนมาลอย ๆ แต่มาจากข้อจำกัดของฟอร์เวิร์ดคอนเวอร์เตอร์ ที่ต้องมีเวลารีเซ็ตแกนหม้อแปลง
ในช่วงออฟ ทำให้ดิวตี้ต้องต่ำกว่า 0.5 และ `0.41` คือค่าที่เผื่อระยะไว้ใต้ลิมิตนั้น
นี่คือเหตุผลที่โค้ดมี `static_assert` กันไม่ให้ตั้ง `DUTY_MAX` เกิน 0.5

ค่าที่ Display แสดงคือ `0.41` เพราะดิวตี้ชนลิมิตบนอยู่ ไม่ใช่ค่าที่คำนวณได้พอดี

## ตารางเทียบบล็อกกับโค้ด

| บล็อกใน Simulink | ตำแหน่งในโค้ด |
| --- | --- |
| Constant `58`, `5` | `V_REF`, `I_REF` ใน `config.h` |
| Zero-Order Hold12 / Hold13 | การอ่าน ADC หนึ่งครั้งต่อรอบใน `controlStep()` |
| Sum (setpoint − feedback) | `vRef - vOut`, `iRef - iOut` ใน `CVCCController::update()` |
| Gain `0.1`, `1` | `KP_V`, `KP_I` |
| Gain `0` (ทั้งสองลูป) | `KI_V`, `KI_I` |
| Saturation ทั้งสามตัว (`0` ถึง `0.41`) | `P_SAT_MIN/MAX`, `DUTY_MIN/MAX` |
| Discrete integrator `K*Ts/(z-1)` | `PIController::update()` แบบ Forward Euler |
| Sum แบบ `+-` ที่รวม P กับ I | `I_TERM_SIGN` |
| บล็อก `min` | การเลือกใน `CVCCController::update()` |
| บล็อก `D -> P` | `pwmWriteDuty()` ใน `pwm.h` ที่ 67 kHz |
| Goto tag `[CV]`, `[CC]`, `[Duty]` | ฟิลด์ใน `struct CVCCOutput` |
| Display `0.41` | คอลัมน์ `Duty` ที่พิมพ์ออก Serial |
| Discrete solver step time | `TS_MICROS` (ค่าเริ่มต้น 1 ms) |

## โครงสร้างไฟล์

```
CVCC_Controller/
  CVCC_Controller.ino   สเก็ตช์หลัก: จับจังหวะเวลา, อ่าน ADC, สั่ง PWM, พิมพ์ค่า
  config.h              ค่าปรับตั้งทั้งหมด (setpoint, เกน, ลิมิต, สเกลเซนเซอร์)
  CVCCController.h      สองลูป PI + บล็อก min + saturation ขาออก
  PIController.h        หนึ่งกิ่ง PI ตามที่วาดไว้ในไดอะแกรม
  pwm.h                 ตั้ง Timer1 ให้เป็น PWM 67 kHz และเร่งความเร็ว ADC
  util.h                ฟังก์ชัน saturation
test/
  test_control.cpp      ทดสอบคณิตศาสตร์ของตัวควบคุมบนเครื่องคอมพิวเตอร์
```

## การต่อวงจร (ค่าเริ่มต้น)

| สัญญาณ | ขา |
| --- | --- |
| แรงดันขาออกผ่านตัวแบ่งแรงดัน 150k/10k | `A0` |
| กระแสขาออกจาก ACS712-05B | `A1` |
| PWM ออกไปยัง gate driver | ขา 9 (Uno / Nano / Leonardo) หรือขา 11 (Mega) |

ขา PWM เลือกเองตามบอร์ดใน `pwm.h` เพราะ Timer1 ออกได้เฉพาะขา OC1A เท่านั้น

## ข้อจำกัดสำคัญ: ความละเอียดของ PWM ที่ 67 kHz

เรื่องนี้ควรพิจารณาก่อนตัดสินใจใช้ Arduino กับวงจรนี้ AVR ที่ 16 MHz นับได้เพียง
238 ครั้งต่อคาบสวิตชิ่งที่ 67 kHz จึงได้ผลลัพธ์ดังนี้

| รายการ | ค่า |
| --- | --- |
| ความถี่ที่ได้จริง | 67,227 Hz (คลาดจากเป้า +0.34% เพราะการหารลงตัวของตัวนับ) |
| จำนวนสเต็ปของดิวตี้ | 238 สเต็ป ประมาณ 7.9 บิต |
| ดิวตี้ต่อหนึ่งสเต็ป | 0.42% |
| สเต็ปที่ใช้งานได้จริงในช่วง 0 ถึง 0.41 | 98 สเต็ป |
| แรงดันขาออกต่อหนึ่งสเต็ป | ราว 0.59 V (คิดจากอัตราส่วนรอบที่ให้ 58 V ที่ดิวตี้ 0.41) |

ราว 0.59 V ต่อหนึ่งสเต็ปถือว่าหยาบสำหรับโหมด CV ของเครื่องประจุไฟ ในทางปฏิบัติ
ลูปจะแกว่งไปมาระหว่างสองสเต็ปที่ขนาบค่าเป้าหมายอยู่ ถ้าต้องการความละเอียดกว่านี้
มีสองทาง คือย้ายไปใช้ไมโครคอนโทรลเลอร์ที่นาฬิกาสูงกว่า (ESP32, STM32 หรือ RP2040
ให้ราว 10 บิตที่ 67 kHz ต้องเขียน `pwm.h` ใหม่เฉพาะไฟล์เดียว) หรือใช้ไอซีควบคุม PWM
แยกและให้ Arduino ทำหน้าที่กำกับดูแลอย่างเดียว

สเก็ตช์รายงานความถี่และจำนวนสเต็ปที่ได้จริงออก Serial ตอนเริ่มทำงาน และรายงานเวลาที่
ใช้ต่อหนึ่งรอบควบคุมในคอลัมน์สุดท้าย เอาไปเทียบกับ `TS_MICROS` ได้ว่าบอร์ดเหลือกำลัง
ประมวลผลแค่ไหน

## สิ่งที่ต้องแก้และระวังก่อนต่อวงจรจริง

1. **สเกลของเซนเซอร์** ค่าเริ่มต้นตั้งไว้สำหรับตัวแบ่งแรงดัน 150k/10k
   (`V_SENSE_GAIN = 16`, ทำให้ 58 V เหลือ 3.6 V ที่ขา ADC) และ ACS712-05B
   (`I_SENSE_OFFSET_V = 2.5`, `I_SENSE_GAIN = 5.405`) ถ้าใช้ฮาร์ดแวร์อื่นต้องแก้
   ให้ตรง มิฉะนั้นตัวควบคุมจะอ่านค่าผิดและสั่งดิวตี้ผิดไปทั้งหมด
2. **ต้องมีตัวกรอง RC ที่สายวัด** ไดอะแกรมมีแต่ ZOH ไม่มีโลว์พาส แต่ของจริงมีริปเปิล
   67 kHz ปนมา และการสุ่มที่ 1 kHz จะทำให้ริปเปิลนั้นพับกลับ (alias) เข้าลูปควบคุม
   แนะนำ 4.7 kΩ ต่ออนุกรมกับ 47 nF ลงกราวด์ ได้ความถี่ตัดราว 720 Hz ซึ่งลดทอน
   67 kHz ได้ประมาณ 39 dB
3. **ตัวเก็บประจุที่ขา ADC ช่วยเรื่องอิมพีแดนซ์ด้วย** ตัวแบ่ง 150k/10k มีอิมพีแดนซ์
   ขาออกราว 9.4 kΩ ซึ่งสูงเกินกว่าที่ ADC ของ AVR ชอบ ยิ่งเมื่อเร่งนาฬิกา ADC เป็น /32
   ตัวเก็บประจุ 47 nF ที่ขาจะทำหน้าที่เป็นแหล่งประจุให้วงจร sample-and-hold
4. **ต้องมี gate driver แบบแยกกราวด์** สวิตช์อยู่ทางด้านไพรมารีที่ 155 V ส่วน Arduino
   ควรอยู่ด้านเซคันดารี จึงต้องใช้ไดรเวอร์แบบออปโตหรือหม้อแปลงขับเกตคั่น
   ขา PWM ของ Arduino ขับเกตมอสเฟตกำลังโดยตรงไม่ได้
5. **ป้องกันขา ADC** แรงดันที่เข้าขาอนาล็อกต้องไม่เกิน 5 V ในทุกกรณี รวมถึงตอนเกิด
   ความผิดพร่อง
6. **ยังไม่มีการจำกัดกระแสแบบรอบต่อรอบ** ตัวควบคุมนี้วัดกระแสขาออกที่ผ่านตัวเหนี่ยวนำ
   แล้ว จึงเป็นกระแสเฉลี่ย ไม่เห็นกระแสยอดของสวิตช์ ถ้าเกิดโหลดกระชากหรือหม้อแปลง
   เข้าสู่ภาวะอิ่มตัว ลูปที่ทำงานทุก 1 ms ตอบสนองไม่ทัน ควรมีวงจรตัดทางฮาร์ดแวร์เสริม

## ข้อสังเกตเรื่องพฤติกรรมของตัวควบคุม

- **บล็อก Sum ที่รวม P กับ I เป็นแบบ `+-` คือลบค่าอินทิกรัลออก** ผลคือถ้าตั้ง `Ki`
  ให้มากกว่าศูนย์ จะกลายเป็นป้อนกลับเชิงบวก เพราะค่าผิดพลาดที่ค้างอยู่จะดันเอาต์พุต
  ให้ห่างจากค่าเป้าหมายมากขึ้นเรื่อย ๆ โมเดลยังเสถียรอยู่ได้เพราะ `Ki = 0` ทั้งสองลูป
  ควรแก้เครื่องหมายในโมเดลก่อนเริ่มจูนค่าอินทิกรัล โค้ดเก็บพฤติกรรมนี้ไว้ตามโมเดลผ่าน
  `I_TERM_SIGN` และมีเทสต์ยืนยันไว้ เพื่อให้ชัดว่าไม่ใช่ความผิดพลาดจากการแปลง
- เมื่อ `Ki = 0` ตัวควบคุมเป็นแบบ P ล้วน ผลคือเมื่อค่าผิดพลาดเป็นศูนย์ ดิวตี้ก็เป็นศูนย์ด้วย
  แรงดันขาออกจึงนิ่งอยู่ต่ำกว่า 58 V เสมอ (steady-state error)
- ด้วยลิมิต `0.41` และ `KP_V = 0.1` กิ่ง CV จะชนลิมิตบนตลอดช่วงที่แรงดันขาออกต่ำกว่า
  53.9 V และกิ่ง CC จะชนลิมิตบนตลอดช่วงที่กระแสต่ำกว่า 4.59 A ในช่วงที่ทั้งสองกิ่ง
  อิ่มตัวพร้อมกัน (เช่นตอนเริ่มจ่ายไฟ) บล็อก `min` แยกไม่ออกว่าลูปไหนกำลังคุมอยู่
  ค่าในคอลัมน์ `mode` จึงไม่มีความหมายในช่วงนั้น
- ลิมิตล่างที่เป็นศูนย์ทำให้เมื่อแรงดันเกินเป้า กิ่ง CV กระโดดไปเป็นศูนย์ทันที ไม่ได้ลด
  ลงอย่างต่อเนื่อง ถ้าโหลดเบามาก ๆ อาจเห็นดิวตี้กระพริบระหว่าง 0 กับค่าใช้งาน
  ซึ่งเป็นพฤติกรรมของตัวโมเดลเอง ไม่ใช่ผลจากการแปลงเป็นโค้ด
- โค้ดเพิ่มการจำกัดค่าสะสมของอินทิเกรเตอร์ (`I_SAT_MIN` / `I_SAT_MAX`) ซึ่งบล็อก
  อินทิเกรเตอร์ธรรมดาใน Simulink ไม่มี เพราะบนฮาร์ดแวร์จริง ค่าสะสมที่ไม่ถูกจำกัดจะใช้
  เวลาหลายวินาทีในการคลายตัวหลังเกิดความผิดพร่อง
- รอบควบคุม 1 ms เท่ากับหนึ่งรอบต่อ 67 รอบสวิตชิ่ง สำหรับเครื่องประจุแบตเตอรี่ที่มี
  พลวัตช้าถือว่าเพียงพอ แต่แบนด์วิดท์ของลูปจะถูกจำกัดด้วยอัตรานี้ ไม่ใช่ด้วยความถี่สวิตชิ่ง
- การตั้ง Timer1 ใหม่ทำให้ `analogWrite()` บนขา 10 (OC1B) ใช้ไม่ได้ ส่วน `millis()`,
  `delay()` และ `micros()` ยังทำงานปกติเพราะใช้ Timer0
- `pwm.h` เร่งสัญญาณนาฬิกาของ ADC เป็น /32 เพราะที่ความเร็วเริ่มต้น การอ่านค่าหนึ่งครั้ง
  ใช้เวลาราว 112 µs ซึ่งกินเวลาเกือบทั้งรอบ 1 ms

## การทดสอบ

ทดสอบคณิตศาสตร์ของตัวควบคุมบนเครื่องคอมพิวเตอร์ ไม่ต้องมีบอร์ด เพราะไฟล์ส่วนตัวควบคุม
ไม่ได้เรียกใช้ฟังก์ชันของ Arduino เลย จึงเป็นโค้ดชุดเดียวกับที่รันบนบอร์ดจริง:

```bash
make -C test
```

เทสต์ตัวแรกใช้ค่าจากสโคปในโมเดลเป็นตัวเทียบ คือที่ `V_OUT = 51.33` V และ
`I_OUT = 4.59` A กิ่ง CV ชนลิมิตบน ส่วนกิ่ง CC พอดีที่ลิมิตเพราะ `1.0 × (5 − 4.59)`
เท่ากับ `0.41` ทำให้ดิวตี้ออกมาเป็น `0.41` ตรงกับที่ Display แสดง

คอมไพล์สเก็ตช์:

```bash
arduino-cli compile --fqbn arduino:avr:uno CVCC_Controller
```

อัปโหลดลงบอร์ด:

```bash
arduino-cli upload --fqbn arduino:avr:uno --port /dev/ttyUSB0 CVCC_Controller
```

เปิดดูค่าที่ส่งออกมา (115200 baud) จะได้ข้อมูลแบบ CSV ที่นำไปพลอตต่อได้ หน้าตาประมาณนี้
โดยคอลัมน์สุดท้ายเป็นค่าที่วัดได้จริงบนบอร์ดที่ใช้ จึงต่างกันไปตามรุ่น

```
# pwm 67226 Hz, 238 steps, step budget 1000 us
# V,I,CV,CC,Duty,mode,peakStepUs
51.33,4.590,0.410,0.410,0.410,CC,...
```
